Paid / Unpaid document status
A document can be marked Paid or Unpaid from the History Browser or from the open document. The state is stored inside the snapshot itself, so it follows the document to every device and survives sync. Releasing an invoice always refreshes the pool immediately — no app restart.

i Behaviour summary
Paid
Stored with the document: paid: true, paid_at, paid_by inside the snapshot JSON. No Supabase schema migration; the existing snapshot update/sync carries it to every device.
Unpaid
Default for every existing document — no flag needed. Legacy snapshots show as Unpaid without being rewritten.
Toggle
Where: history card action, open-document sidebar, and (optional) a compact switch in the document toolbar. The two views stay in sync because both write the snapshot and refresh the list.
Release
When marking unpaid the dialog offers “Release invoices back to the pool”. Releasing updates local SQLite, Supabase and the rendered pool list in one action, so the invoice is immediately claimable elsewhere.
Guard
Marking paid keeps claims locked to the document; the existing double-pay warning still flags an invoice that also appears in another document.
